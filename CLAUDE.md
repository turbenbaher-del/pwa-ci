# CLAUDE.md — ДБО Центр-инвест, PWA

## Что это

Progressive Web App для юрлиц банка «Центр-инвест»: счета, платежи, выписки,
контрагенты, аналитика, разделы ДБО. Ставится на домашний экран iPhone и Android.
Владелец — Сергей (`turbenbaher@gmail.com`), сотрудник банка.

Данные приложение берёт **не напрямую из банка**, а через отдельный сервис-прокси
(репозиторий `centrinvest-proxy`), который управляет веб-версией ДБО через Playwright.
У ДБО нет публичного API — это принципиальное ограничение, из него растут почти все
особенности ниже.

## Стек и команды

React 18 + TypeScript + Vite 4, zustand для состояния, vite-plugin-pwa (workbox).

```bash
npm install
npm run dev                     # localhost:5173
npm run build                   # сборка в dist/
npx tsc --noEmit                # проверка типов
node scripts/gen-icons.mjs       # иконки и splash из логотипа
node scripts/gen-screenshots.mjs # скриншоты экранов и для манифеста
```

Скрипты требуют `playwright-chromium`. Если его нет в проекте, укажите соседний:
`PW_MODULES="../Центр-инвест/centrinvest-proxy/node_modules" node scripts/gen-icons.mjs`

Локальный просмотр сборки: `npx vite preview --port 4173 --host 127.0.0.1`
(без `--host 127.0.0.1` сервер слушает только IPv6, и браузер до него не достучится).

## Деплой

GitHub Pages, репозиторий `turbenbaher-del/pwa-ci`, ветка `main` → GitHub Actions
→ `gh-pages`. Живой адрес: https://turbenbaher-del.github.io/pwa-ci/

Адрес и токен прокси подставляются при сборке из секретов репозитория:
`VITE_PROXY_URL`, `VITE_PROXY_TOKEN`. В коде их быть не должно.

`base` сборки — `/pwa-ci/`. Для своего домена: `VITE_BASE=/ npm run build`.

## Структура

- `src/utils/api.ts` — единая точка обращения к прокси. Все запросы идут через
  `apiFetch`/`apiFetchBlob`, они подставляют токен. Не звать `fetch` напрямую.
- `src/utils/format.ts` — деньги, валюты, статусы счетов, имена. Логика
  централизована здесь: раньше проверки валюты и статуса дублировались по страницам
  и разъехались (главная складывала рубли с долларами).
- `src/store/` — zustand: auth, accounts, payments, contractors, templates,
  notifications, theme, confirm.
- `src/pages/` — экраны. `SectionPage.tsx` — универсальный экран разделов ДБО.
- `src/styles/` — global.css (токены брендбука), layout, navigation, pages.
- `scripts/` — генераторы иконок и скриншотов.
- `public/` — иконки, maskable, apple-touch, splash, favicon. **Генерируются скриптом**,
  руками не править.

## Правила

- Общение и комментарии в коде — на русском.
- **Никаких учётных данных в коде и на экранах.** Логин и пароль ДБО были напечатаны
  в подвале экрана входа и в README — то есть опубликованы в интернете. Это исправлено,
  повторять нельзя.
- Цвета и шрифты — только из токенов в `global.css` (брендбук v1.0.1: зелёный
  `#50B848`, Montserrat + Roboto). Не вводить свои цвета в компонентах.
- Валюты не складывать между собой: суммарный остаток считается только по рублёвым
  счетам (`sumRubleBalance`). Банк отдаёт код `RUR`, в Intl нужен `RUB` —
  для этого `normalizeCurrency`.
- Статусы счетов приходят по-разному (`active`, `Открыт`) — сравнивать через
  `isAccountOpen`, показывать через `accountStatusLabel`.
- После правок: `npx tsc --noEmit`, затем `npm run build`. Экраны удобно проверять
  `scripts/gen-screenshots.mjs` — он же ловит ошибки консоли.

## Особенности PWA, которые легко сломать

- `scope` и `start_url` в манифесте обязаны совпадать с `base`. При расхождении
  установка молча перестаёт работать.
- Service worker регистрируется по `${import.meta.env.BASE_URL}sw.js`. Путь `/sw.js`
  в корне даёт 404 при деплое в подпапку.
- `viewport-fit=cover` в `index.html` обязателен, иначе `env(safe-area-inset-*)`
  на iPhone всегда 0. Safe-area учитывается точечно — в шапке и нижней навигации;
  общий паддинг у `body` ломает вёрстку.
- Ссылки на ассеты в `index.html` пишутся от корня (`/icon-192.png`) — Vite сам
  подставит `base`.

## Чего приложение не умеет и почему

- **Подписать или удалить документ из ДБО нельзя.** Банк отдаёт операции только
  строками выписки, без идентификатора документа. Подпись доступна только для
  черновиков, созданных в самом приложении (`isLocalDraft`). На экране платежа это
  честно объяснено. Чтобы снять ограничение, нужна разведка документного API —
  см. `recon-documents` в репозитории прокси.
- **Push на закрытое приложение не приходит.** У ДБО нет вебхуков, прокси читает банк
  по запросу. Уведомления строятся из реальных операций и показываются при открытом
  или обновлённом приложении. Настоящий push потребует опроса банка по расписанию —
  это нерешённый вопрос к владельцу.
- **Разделы ДБО** (кредиты, депозиты, эквайринг, АУСН и прочие) читаются перехватом
  JSON банка. Механизм рабочий, но подписи пунктов меню подгонялись не на всех
  разделах — часть может открываться пустой.

## Демо-режим

Кнопка «Войти в демо-режиме» показывает интерфейс на тестовых данных без обращения
к банку (`src/utils/demo.ts`). Удобно для проверки вёрстки и для показа.
